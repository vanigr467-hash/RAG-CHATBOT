# 🤖 RAG Chatbot

A web application where users upload PDFs and ask questions, and AI answers using information retrieved from the uploaded documents together with LLM knowledge.

## 1. Description

RAG Chatbot is a complete, working Retrieval-Augmented Generation (RAG) demo application. Users upload one or more PDF documents, the app indexes them into a local vector database, and a chat interface lets users ask questions. Answers are generated by a Groq-hosted LLM, grounded in the most relevant retrieved passages when available, and clearly labeled as coming from the documents, general LLM knowledge, or both.

## 2. Features

- Upload one or multiple PDF files
- Automatic text extraction, cleaning, and chunking
- Local embeddings via a Hugging Face sentence-transformer model
- FAISS vector database for semantic similarity search
- Configurable chunk size, chunk overlap, and number of retrieved chunks
- Groq LLM integration with a configurable model (via `.env`)
- Chat interface with persistent history and follow-up question support
- Source citations (document name + page number) for document-grounded answers
- Clear distinction between document-based and general-knowledge answers
- "Clear Chat" and "Reset Knowledge Base" controls (with confirmation)
- Knowledge base status indicator (documents indexed, chunk count)
- Friendly error handling for missing keys, corrupted PDFs, API failures, etc.

## 3. Architecture

```
PDF Upload
   ↓
PDF Text Extraction (PyPDFLoader)
   ↓
Text Cleaning
   ↓
Text Chunking (RecursiveCharacterTextSplitter)
   ↓
Embedding Generation (sentence-transformers/all-MiniLM-L6-v2)
   ↓
FAISS Vector Database
   ↓
Semantic Similarity Search
   ↓
Relevant Context Retrieval
   ↓
Groq LLM (llama-3.3-70b-versatile by default)
   ↓
Final Answer
   ↓
Streamlit Chat Interface
```

## 5. RAG Workflow

1. **Upload** — user uploads one or more PDFs via the sidebar.
2. **Build Knowledge Base** — the app extracts text page-by-page, cleans whitespace, and splits it into overlapping chunks, each tagged with its source filename and page number.
3. **Embed & Index** — chunks are embedded with a local sentence-transformer model and stored in a FAISS index (also persisted to `faiss_index/`).
4. **Ask** — the user asks a question in the chat box.
5. **Retrieve** — the question is embedded and used to search FAISS for the top-k most similar chunks; chunks below a relevance threshold are discarded.
6. **Generate** — retrieved context, recent chat history, and the question are assembled into a prompt and sent to the Groq LLM.
7. **Answer** — the LLM's answer is displayed along with a label (📚 Document / 🌐 General / 📚+🌐 Both) and an expandable sources list.

## 7. Installation

### 7.1 Prerequisites

- Python 3.10+ installed
- A free Groq API key from [console.groq.com/keys](https://console.groq.com/keys)

### 7.2 Clone / download the project

Place the `rag_chatbot/` folder anywhere on your machine.

### 7.3 Create a virtual environment (Windows)

```
python -m venv venv
```

Activate it:

```
venv\Scripts\activate
```

(On macOS/Linux: `source venv/bin/activate`)

### 7.4 Install dependencies

```
pip install -r requirements.txt
```

### 7.5 Configure the Groq API key

Copy `.env.example` to `.env` (already provided as `.env` in this project) and set your key:

```
GROQ_API_KEY=your_groq_api_key_here
MODEL_NAME=llama-3.3-70b-versatile
```

Never commit your real `.env` file — it's already excluded via `.gitignore`.

### 7.6 Run the application

```
streamlit run app.py
```

Streamlit will open the app in your browser, typically at `http://localhost:8501`.

## 8. How to Upload PDFs

1. Open the sidebar.
2. Under **📄 Upload PDFs**, click "Browse files" and select one or more PDF files (max 25MB each).
3. Uploaded filenames and sizes appear as a checklist.

## 9. How to Build the Knowledge Base

1. After uploading PDFs, adjust **RAG Settings** if desired (chunk size, chunk overlap, number of retrieved chunks).
2. Click **🔨 Build Knowledge Base**.
3. Wait for the spinner to finish — the sidebar will show 🟢 Ready along with document and chunk counts.

## 10. How to Ask Questions

1. Type a question into the chat box at the bottom of the main area and press Enter.
2. The assistant answers using retrieved document context, general knowledge, or both — labeled accordingly.
3. Expand **📚 Sources** below an answer to see which document/page it was grounded in and a preview of the retrieved text.
4. Follow-up questions (e.g. "what about its main types?") are understood using recent chat history.

Use **🗑️ Clear Chat** to clear the conversation without touching the indexed documents. Use **♻️ Reset Knowledge Base** to delete the index entirely (a confirmation step is required).

## 11. Troubleshooting

| Problem | Likely Cause / Fix |
|---|---|
| "Groq API key is not configured" | Add `GROQ_API_KEY` to your `.env` file and restart the app. |
| Build Knowledge Base fails on a file | The PDF may be corrupted, empty, or scanned-image-only with no extractable text. Try a different PDF or OCR it first. |
| Answers are slow | Large PDFs or a high chunk/k count increase processing time; reduce chunk count or `k`. |
| "LLM request failed" | Check your internet connection, API key validity, and Groq account rate limits. |
| Embedding model download is slow on first run | The sentence-transformer model downloads once and is cached locally afterward. |
| Old knowledge base reappears after restart | The FAISS index is persisted in `faiss_index/`; use **♻️ Reset Knowledge Base** to clear it. |

## 13. Security Notes

- API keys are read only from environment variables and are never logged, printed, or displayed in the UI.
- Uploads are restricted to `.pdf` files with a 25MB size limit.
- The FAISS index loader in this app only loads indexes this same application previously wrote to `faiss_index/` — never point it at an index directory from an untrusted source.
